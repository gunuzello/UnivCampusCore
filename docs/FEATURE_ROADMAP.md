# HTML 전체 기능 확장 순서

2026-10-05 사용자 요청으로 학생회 MVP 밖의 기능도 순서대로 구현한다. 원본 HTML은 디자인·업무 흐름 참고 자료이며, 아래 단계는 기능 구현 계획이다. 완료율을 임의의 퍼센트로 표시하지 않고 구현·검증 여부를 기록한다.

| 순서 | 영역 | 완료 기준 | 상태 |
|---|---|---|---|
| 1 | 학생회 명단 관리 보강 | 행사·모집 명단 검색, 상태 필터, 질문 답변 포함 CSV, 운영진 권한 검증 | 완료 |
| 2 | 대여사업 | 물품·수량 등록, 대여 가능 재고, 학생 신청, 운영진 수령·반납 처리, 연체·이력 조회, 동시 신청 재고 보호 | 완료 |
| 3 | 동아리 운영 | 조직 유형 구분, 동아리 탐색·가입 처리, 구성원·운영진, 소식·활동, 참석 의사 관리 | 가입·공통 운영·소식 완료, 참석 의사 예정 |
| 4 | 프로그램 탐색 | 프로그램 등록·조회·검색·조건 필터, 상세 안내와 외부 신청 주소 | 예정 |
| 5 | 팀 구하기 | 모집 글·필요 역할, 지원·수락·취소, 팀 구성원과 모집 종료 | 예정 |
| 6 | 운영진 권한 신청·소속 가입 | 가입 신청·검토, 역할 신청·승인, 처리 알림·조직 경계 보호 | 소속 가입 완료, 역할 신청 예정 |
| 7 | 개인 관심과 기회 추천 | 관심 프로필, 저장한 활동, 명확한 기준의 추천과 추천 이유 표시 | 예정 |
| 8 | AI FIND·AI CONNECT | 실제 AI 제공자 연결, 입력·결과 검증, 비용·실패 처리; 연결 전에는 준비 중 표시 | 예정 |

학교 인증은 학교의 인증 방식과 연동 가능 여부가 정해진 뒤 구현한다. Google Drive와 EPiC의 직접 API 연결도 제공자 조건에 맞춰 별도 진행한다. 현재 로컬 MVP에서 외부 서비스 연결을 가장하지 않는다.

## 명단 관리 사용 방법

운영진으로 행사 또는 모집 상세를 열고 신청자/지원자 관리에서 이름·이메일·학과·학번을 검색한다. 상태 필터를 함께 적용할 수 있고 초기화하면 전체 명단으로 돌아온다.

명단 CSV 다운로드는 현재 검색·상태 조건의 결과를 내려받는다. 신청번호, 기본 정보, 처리 상태, 제출 시각(UTC), 질문별 답변을 포함한다. 빈 결과는 헤더만 포함한다. UTF-8 BOM으로 한글을 처리하고 쉼표·따옴표·줄바꿈을 보존한다. 사용자 입력이 스프레드시트 수식으로 실행되지 않도록 텍스트로 출력한다.

내보내기는 서버에서도 조직 운영진/대표 권한을 확인한다. 일반 학생과 일반 구성원은 접근할 수 없다. CSV 응답에는 캐시 금지를 적용한다.

검증: 자동 테스트 15개 통과, TypeScript·Vite 빌드 통과. 브라우저에서 없는 학생 검색, 필터 초기화, 합격 상태 필터, 실제 CSV 다운로드를 확인했다. Downloads의 CSV를 읽어 합격자 1명과 질문 답변 2개를 확인했다.

## 대여사업

소속 → 대여사업. 운영진은 물품 이름·전체 재고·대여 일수·신청 여부를 등록/수정한다. 학생 신청은 즉시 재고를 확보하고 수령 대기 상태가 된다. 학생은 수령 전에 취소할 수 있다. 운영진은 신청을 반려하거나 물품 수령을 처리하고, 수령 시각부터 반납 기한을 계산한다. 반납 처리하면 재고가 반환되고 이력은 보존된다. 운영 관리에서 상태·연체·이름·물품 검색이 가능하다. 내 대여에는 모든 조직의 본인 기록을 표시한다.

재고 변경, 신청, 취소, 수령·반납은 물품 행 잠금으로 직렬화한다. 요청/대여 중인 수량 아래로 재고를 줄일 수 없고 한 사용자의 같은 물품 활성 신청은 한 건으로 제한한다. 비활성 물품은 새 신청만 막으며 기존 대여는 처리할 수 있다. 일반 학생은 다른 사람의 대여 이력을 볼 수 없다.

전체 자동 테스트 19개 통과. 브라우저에서 물품 등록 → 학생 신청·취소·재신청 → 운영진 수령 → 반납 → 재고 복구와 반납 필터를 확인했다. 마지막 물품 동시 신청은 정확히 한 명만 성공했다. 로컬 예시 우산과 가명 학생의 검증 이력은 남겨 두었다.

## 동아리와 소속 가입

찾기 → 동아리에서 실제 등록된 동아리를 검색하고 소개·가입 신청 화면으로 이동한다. 소속 생성 폼에서 학생회/동아리를 선택한다. 신규 유형 필드를 생략한 기존 요청은 학생회로 처리하며 기존 DB의 학생회도 유지한다. 소속의 URL에 조직 ID를 보존해 새로고침과 알림 링크가 같은 조직을 연다.

가입 신청은 PENDING → ACCEPTED/REJECTED/CANCELLED로 처리한다. 대표만 신청 명단을 보고 승인/반려할 수 있다. 승인 시 MEMBER 역할만 부여한다. 운영진·대표 역할은 별도 구성원 관리로 지정한다. 중복 검토 신청, 타 조직의 신청서, 타 사용자 취소는 차단하며 취소·반려 후 재신청할 수 있다. 학생회에도 같은 가입 흐름을 제공한다.

동아리도 조직별 행사·모집·회의·캘린더·대여·기록을 기존 권한 구조로 사용한다. 참석 의사는 후속 보강 대상이다. 자동 테스트 총 22개 통과. 브라우저에서 동아리 생성 → 새로고침 → 학생 탐색·가입 신청 → 대표 승인 → 구성원 등록을 확인했다.

## 소속 소식

소속 화면에서 운영진/대표가 소식을 작성·수정한다. 기본 공개 범위는 구성원 전용이며 전체 로그인 사용자 공개로 변경할 수 있다. 서버에서 구성원 여부를 확인해 전용 소식의 제목·본문을 외부인에게 반환하지 않는다. 신규 소식은 구성원 알림에 등록한다. 소속을 바꾸면 작성 중 폼도 초기화한다.

자동 테스트 총 24개 통과와 프론트엔드 빌드 통과. 공개 범위 변경, 작성 권한, 빈 입력, 타 조직 수정 차단을 확인했다. 로컬 실행 시 생성물 중복 클래스 문제가 다시 발생하지 않도록 실행 전 빌드 결과를 정리하고 시작 클래스를 명시했다.
