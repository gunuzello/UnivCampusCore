# HTML 전체 기능 확장 순서

2026-10-05 사용자 요청으로 학생회 MVP 밖의 기능도 순서대로 구현한다. 원본 HTML은 디자인·업무 흐름 참고 자료이며, 아래 단계는 기능 구현 계획이다. 완료율을 임의의 퍼센트로 표시하지 않고 구현·검증 여부를 기록한다.

학교 인증은 학교의 인증 방식과 연동 가능 여부가 정해진 뒤 구현한다. Google Drive와 EPiC의 직접 API 연결도 제공자 조건에 맞춰 별도 진행한다. 현재 로컬 MVP에서 외부 서비스 연결을 가장하지 않는다.

## 명단 관리 사용 방법

운영진으로 행사 또는 모집 상세를 열고 신청자/지원자 관리에서 이름·이메일·학과·학번을 검색한다. 상태 필터를 함께 적용할 수 있고 초기화하면 전체 명단으로 돌아온다.

명단 CSV 다운로드는 현재 검색·상태 조건의 결과를 내려받는다. 신청번호, 기본 정보, 처리 상태, 제출 시각(UTC), 질문별 답변을 포함한다. 빈 결과는 헤더만 포함한다. UTF-8 BOM으로 한글을 처리하고 쉼표·따옴표·줄바꿈을 보존한다. 사용자 입력이 스프레드시트 수식으로 실행되지 않도록 텍스트로 출력한다.

내보내기는 서버에서도 조직 운영진/대표 권한을 확인한다. 일반 학생과 일반 구성원은 접근할 수 없다. CSV 응답에는 캐시 금지를 적용한다.

검증: 자동 테스트 15개 통과, TypeScript·Vite 빌드 통과. 브라우저에서 없는 학생 검색, 필터 초기화, 합격 상태 필터, 실제 CSV 다운로드를 확인했다. Downloads의 CSV를 읽어 합격자 1명과 질문 답변 2개를 확인했다.

## 대여사업

소속 → 대여사업. 운영진은 물품 이름·전체 재고·대여 일수·신청 여부를 등록/수정한다. 학생 신청은 즉시 재고를 확보하고 수령 대기 상태가 된다. 학생은 수령 전에 취소할 수 있다. 운영진은 신청을 반려하거나 물품 수령을 처리하고, 수령 시각부터 반납 기한을 계산한다. 반납 처리하면 재고가 반환되고 이력은 보존된다. 운영 관리에서 상태·연체·이름·물품 검색이 가능하다. 내 대여에는 모든 조직의 본인 기록을 표시한다.

재고 변경, 신청, 취소, 수령·반납은 물품 행 잠금으로 직렬화한다. 요청/대여 중인 수량 아래로 재고를 줄일 수 없고 한 사용자의 같은 물품 활성 신청은 한 건으로 제한한다. 비활성 물품은 새 신청만 막으며 기존 대여는 처리할 수 있다. 일반 학생은 다른 사람의 대여 이력을 볼 수 없다.

전체 자동 테스트 19개 통과. 브라우저에서 물품 등록 → 학생 신청·취소·재신청 → 운영진 수령 → 반납 → 재고 복구와 반납 필터를 확인했다. 마지막 물품 동시 신청은 정확히 한 명만 성공했다. 로컬 예시 우산과 가명 학생의 검증 이력은 남겨 두었다.
